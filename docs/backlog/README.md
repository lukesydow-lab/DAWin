# DAWin Backlog

**Status: Current**
**Last updated:** 2026-05-31
**Owner:** PM / Tech Lead

This folder contains the product backlog operating model for DAWin. Use it to separate demo-critical work from post-MVP, nice-to-make, and blue-sky ideas.

## Start here

1. [`DAWin_BACKLOG.md`](DAWin_BACKLOG.md) — master backlog, tier definitions, Sprint 9 candidate stack, and work-order guidance.
2. [`feature-intake-template.md`](feature-intake-template.md) — template for turning a new idea into a triage-ready backlog item.

## Backlog tier meanings

| Tier | Meaning |
|---|---|
| Need-to-Have | Required for the socializable MVP/demo promise or core DAWin collaboration promise. |
| Post-MVP | Important and likely needed, but not required for first musician testing. |
| Nice-to-Make | Useful polish or workflow speed, but not demo-blocking. |
| Blue Sky / Needs Discovery | Big ideas with meaningful product, legal, design, or technical unknowns. |

## Promotion rule

A backlog item may not become sprint work until it has:

1. PM priority confirmation.
2. Tech Lead architecture review.
3. Designer spec in `docs/specs/` if user-visible.
4. Clear acceptance criteria.
5. Work order in `docs/handoffs/active/` or a GitHub issue tied to the sprint.

This exists to keep DAWin from becoming a gorgeous idea meteor shower with no landing pad.
